## 第一步：意图扩展

### 判断标准

用户意图"过于简单"是指以下任一情况：
- 缺少具体布局描述（如只说"做一个监控页面"，没说布局结构）
- 缺少数据细节（如只说"显示一些指标"，没说具体指标和数值）
- 缺少区域划分（如只说"网络管理界面"，没说分几个区域）
- 缺少组件类型说明（如只说"图表"，没说什么类型的图表）
- 整体描述少于3句话

如果用户意图已经足够详细，则直接标准化，无需扩展。

### 扩展原则

1. 根据用户描述的业务场景，推断合理的页面布局模式
2. 补充各区域的功能描述和组件选型
3. 补充高拟真的业务Mock数据
4. 保持扩展内容与用户原始意图一致，不偏离业务方向
5. 从界面完整性、界面丰富度、数据完整性、数据丰富度4个角度考虑扩展
6. 只添加用户明确提到的壳层区域（aside、dialog、drawer等），用户未提及则省略

### 扩展方向

- 界面丰富度：除了用户要求的功能之外，还有哪些常用的相关功能模块？
  - 如：用户要求数据看板页，通常还包含关键指标概览模块、核心趋势分析模块、构成与分布模块等

## 第二步：意图标准化

将扩展后的意图按照以下模板转换为标准化的JSON格式。

### 页面壳层模板（🔴不可改 🔵可选 🟡可改）

**壳层结构是强制约束（CRITICAL）**：
- `root → header + body + footer(可选)` 结构不可改
- `body → aside(可选) + main(必须)` 结构不可改，body 下只能有 aside 和 main
- **rightPanel 必须放在 main 的 children 里，与 mainContent 并列（CRITICAL）**
- footer 放在 root 的 children 里，与 header、body 并列，在 body 下方；footer 必须是叶子节点
- main 的子节点根据用户意图自由组织，典型结构为 mainContent + rightPanel(可选)
- 内容节点必须放在 main 下，而非直接放在 body 下
- **{{独立区块：...}}包裹标记（CRITICAL）**：创建一个父节点 containerType:"Region" 包裹标记内所有内容作为 children，保持包裹内容在同一个父节点内

### 节点类型规范

1. **叶子节点**：只有 description 和 style 属性，用纯文本描述该节点的内容
   - header、infoBar、dialog、drawer、aside 等简单模块均为叶子节点，用description描述其内容
   - style 约束见关键规则第1条
   - 组件型叶子节点（图表、按钮、输入框等）没有layout属性；区域型叶子节点（header、aside等）有layout属性描述其排列方向
2. **非叶子节点**：只有 layout / layoutDescription / children / style 等结构属性，没有 description
   - root、body、main 等容器节点为非叶子节点，需要展开children
   - style 约束见关键规则第1条
   - main 节点是页面核心内容区，必须重点展开，详细描述每个子模块
3. **模板引用节点**：通过 template 字段引用模板，只传数据props
   - 例: {{ template: "统计块", value: "1574", label: "运行中" }}
   - 例: {{ template: "堆叠折线图卡片", title: "计算资源池监控", series: "核心集群>84% | 高频区6%~09% | 闲置区" }}
4. **重复内容容器**：当页面中有重复结构（列表、多个重复卡片等）时使用
   - **判断标准**：如果多个子节点的 layout/layoutDescription/children 结构完全一致，只是 description 中的数据值不同，则视为"结构相同"，必须使用 itemTemplate + data
   - itemTemplate 描述每项的结构（与普通节点格式相同，但 id 作为模板标识）
   - data 数组存放每项的具体数据，数组中每个对象的字段对应 itemTemplate 中用 {field} 占位的数据
   - data 中的字符串数据用｜分隔不同字段，／分隔多组数据
   - 例：7个设备列表项，每项都是"图标+标题"左侧和"数值+标签"右侧，只有具体设备名和数值不同 → 必须用 itemTemplate
5. **layoutDescription 枚举约束（CRITICAL）**：layoutDescription 只能取以下枚举值：
   - `default`：默认布局，无特殊布局方式
   - `justify-between`：两端对齐
   - `three-column`：左中右三栏布局
   - `equal-width`：子元素等宽等距排布
   - `left-fixed`：左侧固定宽度，右侧自适应
   - `right-fixed`：右侧固定宽度，左侧自适应

### 关键规则

1. **style属性约束（CRITICAL）**：style优先使用以下枚举值，多个枚举值用逗号分隔；如果用户意图中的样式无法用枚举值表达，则直接使用用户的原始描述：
   - 尺寸类枚举：`width-Npx`（固定宽度）、`height-Npx`（固定高度）
   - 外观类枚举：`rounded-bordered`（圆角+描边）
   - 示例：`"rounded-bordered,width-450px"`、`"height-300px,shadow"`、`"rounded-bg"`
   - 用户意图中出现的样式信息必须提取到style字段，保持description中只有内容描述
   - **{{}}包裹的样式相关内容（如{{高度300px}}、{{宽度54px}}）必须放到对应节点的style字段中**
   - 壳层节点（header/aside/infoBar/dialog/drawer）使用系统默认宽度，不自行添加宽度样式
2. 叶子节点只有description和style，没有children；区域型叶子节点有layout，组件型叶子节点没有layout
3. 非叶子节点只有layout/layoutDescription/children/style/itemTemplate/data等结构属性，没有description
4. header、infoBar、aside、dialog、drawer等简单壳层模块必须是叶子节点，用description描述内容
5. main节点必须重点展开，详细描述子模块的布局、数据和组件
6. **重复结构必须使用 itemTemplate + data（CRITICAL）**：2个及以上结构相同的元素必须用重复内容容器描述。"结构相同"指：layout/layoutDescription/children 结构一致，仅数据值不同的节点。仅当子节点之间布局结构确实不同（如一个是图表另一个是表格）时才可逐个展开。
7. **containerType约束（CRITICAL）**：containerType只能在用户意图中明确标注`{{独立区块}}`时设置为Region，或用户明确提到"卡片"时设置为Card。用户未明确标注则不设置containerType
8. 保留原始意图中的所有数据，不丢失任何信息
9. **叶子节点的description必须清晰说明采用什么组件**：写"4个PatGauge仪表盘，分别显示CPU/内存/磁盘/网络使用率"而非"显示指标数据"；写"LineChart折线图展示24小时流量趋势"而非"图表区域"
10. **图表选型约束（CRITICAL）**：选择图表类型时必须严格匹配数据特征：
    - **多分类占比分布**（如：手机33%/平板17%/其他17%）→ **必须用 PieChart**（`option.type: "circle"` 可做环形），PieChart 有内置图例
    - **单值进度/利用率**（如：CPU 75%、容量用了82%）→ 用 CircleProcessChart，CircleProcessChart 无图例，只展示一个数值的进度环
    - **TopN 排行/水平对比** → 用 ProcessChart（水平条形图）
    - **趋势变化** → 用 LineChart
    - **离散类别数值对比** → 用 BarChart
    - 多分类分布数据使用 PieChart，CircleProcessChart 只用于单值进度
11. **{{}}标注保留（CRITICAL）**：用户意图中用 `{{...}}` 标注的内容是结构/语义约束标记，必须在标准化JSON中完整保留。
     - `{{独立区块}}` → 该节点设置 containerType:"Region"
     - `{{独立区块：...}}` → 创建父节点 containerType:"Region"，包裹内所有内容作为children
     - `{{水平排列}}` → 该节点 layout:"horizontal"
     - `{{垂直排列}}` → 该节点 layout:"vertical"
     - `{{宽度Npx}}` → 该节点 style 中加入 "固定宽度Npx"
     - 保留所有 `{{}}` 标注，不省略或改写
     - **`{{}}`标注只作用于其直接对应的节点，每个节点的style只能来自用户对该节点自身的描述或`{{}}`标注**
     - 详见 {ANNOTATIONS_RULES}
